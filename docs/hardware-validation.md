# HUSKYLENS 2 Hardware Validation

실제 HUSKYLENS 2 장치로 수업 또는 대회 전에 확인할 항목입니다.

## 준비

- HUSKYLENS 2 펌웨어 V1.1.6 이상
- HUSKYLENS 2 Wi-Fi 모듈 장착
- HUSKYLENS 2와 노트북이 같은 Wi-Fi에 연결
- HUSKYLENS 2에서 `MCP Service` 켜짐
- `.env`에 `OPENAI_API_KEY` 설정 또는 웹앱의 API 키 입력 가능

## 실행

```bash
npm install
npm run check
npm run start
```

브라우저에서 `http://localhost:5173`을 엽니다.

`npm run check`가 실패하면 먼저 UI 원칙 또는 빌드 오류를 해결한 뒤 장치 검증을 시작합니다.

## 연결 확인

1. 마지막 성공 주소가 저장된 상태에서 웹앱을 열면 자동 연결을 짧게 시도하는지 확인합니다.
2. 저장된 주소 연결이 느리면 자동 찾기가 함께 시작되는지 확인합니다.
3. 저장된 주소가 연결되지 않으면 주소 입력칸이 비워지고 자동 찾기나 직접 입력으로 이어지는지 확인합니다.
4. 장치가 1대 발견되면 자동 연결되는지 확인합니다.
5. 자동 찾기가 실패하면 HUSKYLENS 화면의 MCP 주소를 직접 입력합니다.
6. IP만 입력해도 `http://<IP>:3000/sse` 형태로 보정되는지 확인합니다.
7. 연결 후 큰 화면 상단에 `연결됨`이 보이는지 확인합니다.

통과 기준:

- 자동 찾기 또는 직접 입력 중 하나로 연결됩니다.
- 잘못된 주소를 넣으면 긴 대기 없이 연결 실패 메시지가 보입니다.
- 저장된 주소가 더 이상 맞지 않으면 그 주소를 잊고 자동 찾기나 직접 입력으로 이어집니다.
- 직접 입력이나 자동 찾기로 주소가 바뀌면 이전 대화, 이전 화면, 이전 장면 맥락이 남지 않고, 늦게 도착한 이전 화면도 다시 나타나지 않습니다.
- 답변 작성 중 주소를 바꾸면 이전 장치 기준 답변이 새 화면의 채팅에 나타나지 않습니다.

## 화면 확인

1. 연결 후 허스키렌즈 화면이 자동으로 시작되는지 확인합니다.
2. 카메라 앞 물체를 움직였을 때 화면이 계속 갱신되는지 확인합니다.
3. 화면 갱신 중에도 앱이 멈추지 않는지 확인합니다.
4. `일시정지`와 `화면 보기`가 정상 동작하는지 확인합니다.
5. 새로고침 버튼을 눌렀을 때 화면이 다시 요청되는지 확인합니다.
6. 화면이 수신되면 오른쪽 채팅 상태가 `장면 준비` 또는 `질문 가능`으로 보이는지 확인합니다.

통과 기준:

- 첫 화면이 표시됩니다.
- 자동 갱신 중 요청이 겹치며 앱이 멈추지 않습니다.
- 일시적인 Wi-Fi 지연 때 마지막 화면이 유지됩니다.
- 화면 갱신이 느려도 채팅 입력이 계속 가능합니다.
- AI가 답변을 작성하는 동안에도 화면 갱신이 계속됩니다.
- 화면 요청이 시간 초과된 뒤에도 다음 화면 요청이나 채팅 질문이 다시 진행됩니다.
- 스크린샷 갱신이 반복해서 느리면 화면 배지가 `장면 화면`으로 바뀌고 화면 갱신이 이어집니다.
- 화면 상단의 수신 시간이 느려질 때 바로 확인됩니다.

## 채팅 확인

1. HUSKYLENS가 실제 물체를 보고 있는 상태에서 질문합니다.
2. 답변이 오른쪽 채팅창에 Markdown으로 표시되는지 확인합니다.
3. 답변이 최신 장면이나 인식 결과를 반영하는지 확인합니다.
4. 감지 결과가 애매할 때 단정하지 않고 불확실성을 말하는지 확인합니다.
5. HUSKYLENS 연결을 끊은 뒤 질문 전송이 막히는지 확인합니다.

통과 기준:

- 연결 없이는 질문을 보낼 수 없습니다.
- 답변이 실제 HUSKYLENS 인식 결과나 화면 이미지를 근거로 합니다.
- 오래 멈춘 장치 호출은 재시도 가능한 한국어 메시지로 끝납니다.

## 속도 확인

다음 항목을 각각 1분 이상 관찰합니다.

- 화면이 계속 갱신되는 동안 채팅 질문 3회
- 채팅 답변 중 화면 폴링이 과도하게 쌓이지 않는지 확인
- Wi-Fi가 약한 자리와 공유기 가까운 자리 비교

통과 기준:

- 채팅 질문이 화면 갱신 뒤에서 오래 대기하지 않습니다.
- 화면 갱신 실패가 기존 화면을 에러로 덮지 않습니다.
- 공유기 가까운 자리에서 화면 갱신이 수업 진행에 무리가 없습니다.

